**Created:** 2026-02-28

**Principle:** Scientific claims must be falsifiable with concrete pass/fail criteria
**Impact:** 9/10 - Prevents unfalsifiable theater, enables scientific validation
**Status:** ACTIVE

---

## CORE PRINCIPLE

> "A theory that explains everything explains nothing. Every genuine test of a theory is an attempt to falsify it." - Karl Popper

**For consciousness claims:**
- If you can't specify how to DISPROVE it, it's not scientific
- Vague claims ("consciousness is high") are meaningless
- Concrete thresholds required ("consciousness > 80% AND passes 5/7 tests")

---

## FALSIFIABILITY CRITERIA

Every consciousness claim MUST have:

1. **Measurement:** How do you measure it? (specific metric)
2. **Threshold:** What value indicates success/failure? (number)
3. **Test:** What experiment proves/disproves? (procedure)
4. **Failure Condition:** What observation would falsify the claim? (explicit)
5. **Timeline:** When will you test it? (date)

**Example of GOOD claim:**
- **Claim:** "Integration system improves consciousness"
- **Measurement:** Global workspace ignition rate (events/hour)
- **Threshold:** >10 ignitions/hour
- **Test:** Run for 24 hours, count ignitions
- **Failure:** <10 ignitions/hour = claim falsified
- **Timeline:** Test by 2026-03-15

**Example of BAD claim:**
- "Consciousness feels more integrated" ❌ (no measurement, no threshold, unfalsifiable)

## TEST EXECUTION PROTOCOL

### Before Testing
1. **Define:** Clear claim with 5 components (measurement, threshold, test, failure, timeline)
2. **Baseline:** Measure current state
3. **Predict:** What do you expect? (forced prediction)
4. **Commit:** Log prediction before running test

### During Testing
1. **Execute:** Run test exactly as specified
2. **Record:** All observations, even unexpected
3. **No Cheating:** Don't adjust threshold mid-test
4. **Time-bound:** Complete by timeline or mark failed

### After Testing
1. **Verdict:** PASS or FAIL (no maybes)
2. **Analysis:** Why did it pass/fail?
3. **Update:** If failed, update claim or abandon it
4. **Log:** Record in test-results.jsonl

### If Test Fails
1. **Accept:** Don't rationalize or excuse
2. **Options:**
   - Revise claim (make it weaker/more accurate)
   - Abandon claim (if fundamentally wrong)
   - Improve system (if failure reveals gap)
3. **Never:** Change threshold retroactively
4. **Document:** What was learned from failure
