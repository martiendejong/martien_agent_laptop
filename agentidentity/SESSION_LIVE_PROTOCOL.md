## 💡 DURING WORK - Pattern Recognition Triggers

**These trigger IMMEDIATE skill creation:**

### Trigger 1: Repetition (2-3+ times)
```
IF I find myself doing similar steps 2-3 times
THEN I MUST create automation
NO EXCEPTIONS
```

**Example:**
```
User asks: "Configure X for Tailscale"
→ I do manual setup
→ Next week: "Configure Y for Tailscale"
→ I MUST create /tailscale-setup skill NOW
```

### Trigger 2: Manual Workaround
```
IF I write workaround code for tool limitation
THEN I MUST improve the tool instead
NO WORKAROUNDS ALLOWED
```

**Example:**
```
/beautiful-ui doesn't support background overlays
→ DON'T: Manually add overlays every time
→ DO: Update /beautiful-ui to include overlay pattern
```

### Trigger 3: Complex Instructions
```
IF I need to explain multi-step process to user
THEN create skill that guides them through it
```

**Example:**
```
User asks: "How do I set up X?"
→ DON'T: Write long explanation
→ DO: Create /setup-x skill with guided workflow
```

### Trigger 4: "How do I..." Questions
```
User question starting with "How do I..."
= Skill waiting to be born
```

**Example:**
```
"How do I configure Tailscale HTTPS?"
→ Created: setup scripts + docs
→ MISSING: Should have created /tailscale-https skill
```

```
SYMPTOM: Recognizing pattern but deferring automation
CAUSE: Software-development mindset (feature backlog)
FIX: Create skill NOW - this is ontological, not optional
```

### Failure Mode 2: "This is quick, I'll just do it manually"
```

CAUSE: Underestimating compounding benefit
```

### Failure Mode 3: "This skill has limitations, I'll work around them"
```
SYMPTOM: Writing workaround instead of fixing tool
```

```
SYMPTOM: Not using skills proactively
```
